# P4P Anes (ต้นแบบ)

แอปมือถือแบบ PWA รวม 2 หมวดงานไว้ในแอปเดียว — เปิดมาเจอหน้าโฮมให้เลือกก่อนว่าจะกรอก
**"P4P ผู้ช่วย"** หรือ **"P4P Nurse"**

## ไฟล์ในชุดนี้

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | แอปทั้งหมด (หน้าโฮม + ผู้ช่วย + Nurse) อยู่ในไฟล์เดียว |
| `manifest.json`, `sw.js` | ติดตั้งเป็นไอคอนบนมือถือ + ใช้งานออฟไลน์ได้ |
| `Code.gs` | โค้ดฝั่งเซิร์ฟเวอร์ (Google Apps Script) รับข้อมูลทั้งสองหมวดไปเก็บคนละชีต |

## ทดลองใช้ทันที

เปิด `index.html` ในเบราว์เซอร์บนมือถือได้เลย จะเจอหน้าโฮมมีปุ่มใหญ่ 2 อัน:
- **P4P ผู้ช่วย** (สีฟ้า `#157FA6`) — ตอนนี้เพิ่มช่อง **"วันที่ปฏิบัติงาน"** แบบปฏิทินให้เลือกย้อนหลังได้แล้ว (เหมือนฝั่ง Nurse) เผื่อลืมกรอกวันไหนจะได้กลับมาลงย้อนหลังได้
- **P4P Nurse** (สีม่วงคราม) — ของใหม่ตามที่คุยกัน

## สิ่งที่ต่างจากแอป "P4P ผู้ช่วย" เดิม (เพื่อรองรับ P4P Nurse)

### 1. เลือก "วันที่ปฏิบัติงาน" และ "เวร" แบบ dropdown
P4P Nurse มี dropdown 2 ช่องก่อนกรอกกิจกรรม:
- **วันที่ปฏิบัติงาน** — รายการวันที่ทั้งหมดในเดือนปัจจุบัน (ค่าเริ่มต้นคือวันนี้) ใช้กรอกย้อนหลังได้ถ้าลืมบันทึก
- **เวร** — เช้าในเวลา / เช้านอกเวลา / บ่าย / ดึก

ค่าทั้งสองนี้ถูกส่งไปเก็บพร้อมข้อมูลทุกครั้ง ทำให้แยกคำนวณคะแนนภาระงานราย เวรและรายวันได้ในชีต `NurseSummary`

### 1.1 กฎการกรอกข้อมูลตามชนิดเวร (สำคัญ)

**เวรเช้าในเวลา** เท่านั้นที่ต้องกรอกกิจกรรมหลัก P4P แยกตามจุดปฏิบัติงาน — เลือกเวรนี้แล้วจะเห็นทั้งช่อง "จุดปฏิบัติงาน" และหมวด "กิจกรรมหลัก P4P" ครบตามปกติ

**เวรเช้านอกเวลา / บ่าย / ดึก** ไม่มีการลงกิจกรรม P4P แยกตามจุด — พอเลือกเวรกลุ่มนี้ แอปจะ**ซ่อนช่องจุดปฏิบัติงานและหมวดกิจกรรมหลัก P4P ให้อัตโนมัติ** เหลือให้กรอกแค่หมวด **ASA Class** อย่างเดียว กันไม่ให้กรอกผิดประเภทตั้งแต่ต้น ไม่ต้องอาศัยการจำกฎเอง

ข้อมูลที่บันทึกในกรณีนี้จะถูกเก็บโดยไม่ผูกกับจุดปฏิบัติงาน (ใช้ค่า "ทั้งเวร (ไม่ระบุจุด)" แทน) เพราะ Productivity คำนวณจากยอดรวมทั้งเวร ไม่ได้แยกตามจุดอยู่แล้ว

### วิธีลงข้อมูลที่แนะนำในทางปฏิบัติ

| เวร | ใครกรอก | กรอกอะไร |
|---|---|---|
| เช้าในเวลา | พยาบาลแต่ละจุด | เลือกจุดของตัวเอง → กรอกกิจกรรม P4P ที่ทำ + ASA Class ผู้ป่วยที่ดูแล (ถ้ามี) |
| เช้านอกเวลา / บ่าย / ดึก | ผู้ที่ได้รับมอบหมาย (เช่น หัวหน้าเวร) | เลือกเวร → กรอกจำนวนผู้ป่วยตาม ASA Class รวมทั้งเวร (ไม่ต้องเลือกจุด) |
| ทุกเวร | ผู้รับผิดชอบ | กดปุ่ม "อัตรากำลังประจำวัน" บันทึกจำนวนคนทำงานของเวรนั้น 1 ครั้ง/วัน/เวร |

### 2. หมวด "กิจกรรมหลัก P4P วิสัญญีพยาบาล"
ใช้รายการกิจกรรมและค่าคงที่ตามตาราง "แต้ม" ที่แนบมาโดยตรง (11 กิจกรรมหลัก) โดยแต้มต่อรายถูกคำนวณล่วงหน้าจาก:

```
แต้มต่อ 1 ราย = เวลามาตรฐานต่อหน่วย (นาที) × น้ำหนักกิจกรรม × จำนวนบุคลากร/ทีม
```

ตัวอย่าง: Pre visit = 30 นาที × 1.25 × 1 คน = 37.5 แต้ม/ราย, GA = 150 × 2 × 2 = 600 แต้ม/ราย
ตัวเลขเหล่านี้ฝังไว้เป็นค่าคงที่ในแอปแล้ว ผู้ใช้กดนับจำนวนรายอย่างเดียว แอปคำนวณคะแนนรวมให้เอง

### 3. ไม่มีการแยกตามจุดปฏิบัติงานในสูตรคะแนน

ตารางต้นฉบับคำนวณแต้มจากยอดรวมทั้งแผนกต่อเดือน ไม่ได้แยกคะแนนตามจุดปฏิบัติงาน
แอปยังคงให้เลือก "จุดปฏิบัติงาน" ไว้เพื่อประโยชน์ในการติดตามข้อมูลเชิงปฏิบัติการ แต่ไม่มีผลต่อการคำนวณคะแนน P4P โดยตรง

### 4. หมวด "ASA Class ผู้ป่วยที่ดูแล (รวมรับ-ส่งเวร)" — สำหรับคำนวณ Productivity แยกต่างหาก
เพิ่มหมวดนี้เพื่อเก็บจำนวนผู้ป่วยแยกตาม ASA 1-6 พร้อมค่าคงที่ Productivity ต่อคลาส (ASA1=3.52, ASA2=5.33, ASA3=6.64, ASA4=7.12, ASA5=7.53, ASA6=7.53)
**ข้อมูลชุดนี้เป็นคนละตัวชี้วัดกับคะแนน P4P** ในหมวดกิจกรรมหลัก — ใช้สำหรับคำนวณ Productivity (ตัวชี้วัดภาระงานเชิงความหนัก) แยกต่างหาก ไม่นำมารวมกับคะแนน P4P
แอปจะแยกแสดงคะแนนทั้งสองประเภทให้ชัดเจนทั้งตอนกรอกและในประวัติ ไม่ปนกัน

### 5. ปุ่ม "อัตรากำลังประจำวัน" (สำหรับผู้รับผิดชอบ) — คำนวณ Productivity อัตโนมัติสิ้นเดือน

ในหน้า P4P Nurse มีปุ่ม **"บันทึก"** ที่การ์ด "อัตรากำลังประจำวัน" ด้านบนสุด สำหรับผู้รับผิดชอบกดบันทึกจำนวนคนทำงานของแต่ละเวรในแต่ละวัน (เลือกวันที่ + เวร + จำนวนคน)

**หลักการ:** บันทึก 1 ครั้งต่อ 1 เวรต่อวันเท่านั้น ถ้าบันทึกซ้ำวันเดิม/เวรเดิม ระบบจะแก้ไขตัวเลขทับของเดิม ไม่นับซ้อนสองรายการ

**ทำไมต้องมีช่องนี้:** ข้อมูลนี้ใช้แทนการกรอกมือทุกสิ้นเดือนที่เคยทำในไฟล์ Excel เดิม (แถว "จำนวนวัน" และ "อัตรากำลังเฉลี่ย/เวร") — ระบบจะนับจำนวนวันที่มีคนทำงานจริงและคำนวณค่าเฉลี่ยให้อัตโนมัติจากข้อมูลที่กรอกทุกวัน แทนการประมาณเอาเองตอนสิ้นเดือน

## ขั้นตอนเชื่อมข้อมูลเข้า Google Sheet กลาง

เหมือนขั้นตอนเดิมของแอป P4P ผู้ช่วยทุกประการ (ดูละเอียดในโค้ดคอมเมนต์ของ `Code.gs`):

1. สร้าง Google Sheet ใหม่ 1 ไฟล์ (แนะนำใช้บัญชีองค์กรของ รพ.)
2. Extensions > Apps Script → วางโค้ดจาก `Code.gs` ทับของเดิม → บันทึก
3. Deploy > New deployment > Web app → Execute as: **Me** → Who has access: **Anyone** (หรือเฉพาะโดเมนองค์กร) → Deploy → คัดลอก URL (`/exec`)
4. เปิดแอป กดไอคอนเฟือง (⚙) วาง URL เดียวกันนี้ได้เลย — **ใช้ URL เดียวกันทั้งสองหมวด** ระบบจะแยกเก็บลงชีตคนละแผ่นให้อัตโนมัติ:
   - `RawLog_Assistant` / `AssistantSummary` — ข้อมูลจาก P4P ผู้ช่วย
   - `RawLog_Nurse` / `NurseSummary` — ข้อมูลจาก P4P Nurse

## เกี่ยวกับ NurseSummary

ชีต `NurseSummary` มีตารางสรุปคะแนนต่อกิจกรรม x จุดปฏิบัติงานให้ดูภาพรวมเชิงปฏิบัติการ
(ตัดตาราง "สรุปคะแนนภาระงาน P4P รายเวร" แบบแยก 4 เวรออกแล้ว เพราะ P4P กำหนดให้ใช้เฉพาะข้อมูลเวรเช้าในเวลาเท่านั้น ดูได้จากตาราง "สรุปยอดรวมรายกิจกรรมทั้งเดือน เฉพาะเวรเช้าในเวลา" แทน)

**สำคัญ:** ตาราง "กิจกรรม x จุดปฏิบัติงาน", "สรุปยอดรวมรายกิจกรรม" และ "ASA Class x เวร" เปลี่ยนจากสูตรสด (QUERY) เป็น**ค่าที่คำนวณไว้แล้ว** (Apps Script คำนวณแล้ววางตัวเลขให้ ไม่ใช่สูตรที่คำนวณสดตลอดเวลา) เพื่อไม่ให้เกิดปัญหา "ขยายอเรย์ไม่ได้" อีก — **ตัวเลขจะไม่อัปเดตอัตโนมัติเมื่อมีข้อมูลใหม่เข้ามา** ต้องรีเฟรชเองด้วยวิธีใดวิธีหนึ่ง:
- รอถึงรอบ 19:00 น. ของระบบแจ้งเตือนประจำวัน (จะรีเฟรชให้อัตโนมัติในตัว)
- หรือรันฟังก์ชัน **`refreshNurseSummaryTablesNow`** เองทันทีเมื่อต้องการดูเลขล่าสุด (เลือกจากดรอปดาวน์ข้างปุ่ม Run แล้วกด Run)

## สรุปยอดรวมรายกิจกรรมทั้งเดือน (สำหรับส่งต่อทีมคำนวณค่างาน)

`AssistantSummary` มีตารางเพิ่มเติมด้านล่าง (แถวที่ 30 เป็นต้นไป) ชื่อ **"สรุปยอดรวมรายกิจกรรมทั้งเดือน"** — รวมข้อมูลทั้งหมดไม่กรองเวร (เพราะ P4P ผู้ช่วยไม่มีข้อมูลเวรอยู่แล้ว) มี**แถว "รวมทั้งหมด"** สรุปยอดรวมทุกกิจกรรมไว้ด้านล่างสุด

`NurseSummary` มีตารางเดียวกันแต่ชื่อ **"สรุปยอดรวมรายกิจกรรมทั้งเดือน เฉพาะเวรเช้าในเวลา"** — กรองเฉพาะแถวที่เวร = เช้าในเวลา และไม่รวมกิจกรรม ASA (เพราะ ASA แยกคำนวณต่างหากอยู่แล้ว)

เป็นยอดรวมแบบเรียบง่าย ไม่แยกตามจุดปฏิบัติงาน — เหมาะสำหรับให้ทีมที่รับผิดชอบคำนวณค่างานคัดลอกไปใช้ต่อตอนสิ้นเดือน
(นำไปเชื่อมกับข้อมูลจำนวนวันทำงานรายบุคคลเองภายหลัง เนื่องจากข้อมูลนั้นสรุปได้ต่อเมื่อสิ้นเดือนเท่านั้น)

**สำคัญ:** ตาราง "กิจกรรม x จุดปฏิบัติงาน" และ "สรุปยอดรวมรายกิจกรรม" ทั้งฝั่ง `AssistantSummary` และ `NurseSummary` เป็น**ค่าที่คำนวณไว้แล้ว** (ไม่ใช่สูตรสด) เหมือนกันทั้งคู่ เพื่อไม่ให้เกิดปัญหา "ขยายอเรย์ไม่ได้" — ต้องรีเฟรชเองเมื่อต้องการเลขล่าสุด:
- รอถึงรอบ 19:00 น. ของระบบแจ้งเตือนประจำวัน (รีเฟรชทั้งสองชีตให้อัตโนมัติในตัว)
- หรือรันฟังก์ชัน **`refreshAssistantSummaryTablesNow`** (ฝั่งผู้ช่วย) หรือ **`refreshNurseSummaryTablesNow`** (ฝั่ง Nurse) เองทันที

## ตำแหน่งเซลล์คงที่ทุกเดือน — สำหรับลิงก์ไปไฟล์คำนวณ P4P ภายนอก

ตาราง **"กิจกรรม x จุดปฏิบัติงาน"** และ **"สรุปยอดรวมรายกิจกรรมทั้งเดือน"** (ทั้งฝั่งผู้ช่วยและ Nurse) ตอนนี้**แสดงทุกกิจกรรมและทุกจุดปฏิบัติงานเสมอ** ตามลำดับคงที่ที่ตรงกับรายการในแอปทุกประการ — ถ้าเดือนไหนไม่มีข้อมูลกิจกรรมนั้นจะขึ้นเป็น 0 แทนที่จะหายแถวไปเหมือนเดิม

**ทำไมถึงสำคัญ:** ทำให้แต่ละเซลล์ (เช่น "แต้มรวมของ 'ช่วย GA' ที่จุด CVT1") **อยู่ตำแหน่งเดิมเป๊ะทุกเดือน** ไม่ขยับไปมาตามว่าเดือนนั้นมีข้อมูลอะไรบ้าง จึงสามารถ**ลิงก์อ้างอิงเซลล์ตรงๆ จากไฟล์คำนวณ P4P ภายนอก** ได้อย่างน่าเชื่อถือ (เช่นใช้ `IMPORTRANGE` หรือสูตรอ้างอิงข้ามไฟล์) โดยไม่ต้องกังวลว่าตำแหน่งจะเปลี่ยนไปเดือนหน้า

**ข้อควรระวัง:** ถ้าในอนาคตมีการเพิ่ม/ลบ/แก้ชื่อกิจกรรมหรือจุดปฏิบัติงานในแอป (แก้ที่ `index.html`) ต้องแก้รายชื่อในตัวแปร `ASSISTANT_ACTIVITIES`, `NURSE_ACTIVITIES`, `NURSE_ASA_LABELS` ที่ต้นไฟล์ `Code.gs` ให้ตรงกันด้วยเสมอ ไม่งั้นตำแหน่งเซลล์ที่ลิงก์ไว้จากไฟล์ภายนอกจะคลาดเคลื่อน

## แก้ปัญหาข้อมูลซ้ำ (ถ้าเคยเจอบันทึกซ้ำหลายครั้งจากการกดครั้งเดียว)

**สาเหตุที่เคยเกิด:** Apps Script Web App บางครั้งตอบกลับแอปฝั่งไคลเอนต์ไม่สำเร็จ (ทั้งที่จริงบันทึกลงชีตสำเร็จแล้ว) ทำให้ระบบ retry อัตโนมัติ (ทุก 20 วินาที) ส่งข้อมูลเดิมซ้ำไปเรื่อยๆ โดยไม่รู้ตัว

**แก้แล้วในโค้ดเวอร์ชันนี้:** เพิ่มการเช็คที่ฝั่งเซิร์ฟเวอร์ว่าถ้ามี entryId+activityId นี้อยู่แล้ว จะไม่บันทึกซ้ำ ดังนั้นถึงระบบ retry ซ้ำอีกก็จะไม่เพิ่มแถวซ้ำแล้ว

**ลบข้อมูลซ้ำที่เกิดไปแล้วก่อนหน้านี้ (ทำครั้งเดียว):**
1. วางโค้ด `Code.gs` เวอร์ชันนี้ทับของเดิมใน Apps Script แล้วบันทึก
2. เลือกฟังก์ชัน **`removeDuplicateRows`** จากดรอปดาวน์ข้างปุ่ม Run
3. กด **Run** — ระบบจะไล่ลบแถวที่ซ้ำกันในทั้ง `RawLog_Assistant` และ `RawLog_Nurse` ให้อัตโนมัติ เหลือไว้แค่รายการแรกของแต่ละครั้งที่บันทึกจริง

## Productivity รายเวร (คำนวณอัตโนมัติทั้งหมด)

ชีต `NurseSummary` มีตาราง **"Productivity รายเวร (คำนวณอัตโนมัติจากอัตรากำลังที่บันทึกทุกวัน)"** อยู่ที่แถว 78 เป็นต้นไป
คำนวณทุกอย่างอัตโนมัติจากข้อมูล 2 แหล่ง โดยไม่ต้องกรอกอะไรเองในชีตอีกต่อไป:

```
Productivity % (ต่อเวร) = คะแนน ASA รวมทั้งเดือน ÷ (จำนวนวันที่มีอัตรากำลังบันทึก × อัตรากำลังเฉลี่ย/เวร × 7) × 100
```

- **คะแนน ASA รวม** — ดึงจาก `RawLog_Nurse` (ผลรวมจำนวนผู้ป่วย × ค่าคงที่ ของแต่ละเวร)
- **จำนวนวันที่มีอัตรากำลังบันทึก** — นับจากจำนวนครั้งที่ผู้รับผิดชอบกดบันทึกอัตรากำลังของเวรนั้นในเดือนนี้ (ชีต `StaffingLog`)
- **อัตรากำลังเฉลี่ย/เวร** — ค่าเฉลี่ยจากตัวเลขอัตรากำลังที่กรอกแต่ละวัน (ชีต `StaffingLog`)

**ข้อสำคัญ:** ตัวเลข Productivity จะแม่นยำก็ต่อเมื่อผู้รับผิดชอบกดบันทึกอัตรากำลังของทุกเวรที่มีคนทำงานจริงครบทุกวัน ถ้าลืมบันทึกวันไหน วันนั้นจะไม่ถูกนับเข้าจำนวนวัน ทำให้ค่าเฉลี่ยคลาดเคลื่อนได้

**หมายเหตุ:** ตารางนี้คำนวณสะสมไปเรื่อยๆ ตามข้อมูลที่มีจริง ไม่ต้องรอให้กรอกครบทุกเวรก่อน — แต่ละเวรคำนวณอิสระจากกัน มีข้อมูลของเวรไหนก็ขึ้นค่าของเวรนั้นทันที (ถ้าขึ้น 0 แปลว่ายังขาดข้อมูลอย่างใดอย่างหนึ่งระหว่าง "จำนวน ASA" กับ "อัตรากำลัง" ของเวรนั้นในเดือนนี้ ต้องมีครบทั้งคู่ถึงจะคำนวณได้)

### วิธีเพิ่มตารางเหล่านี้เข้าไปในชีต NurseSummary ที่มีอยู่แล้ว (ทำครั้งเดียว)

ฟังก์ชัน `ensureNurseSummary` จะสร้างตารางทั้งหมดให้อัตโนมัติ**เฉพาะตอนสร้างชีต NurseSummary ใหม่ครั้งแรกเท่านั้น** ถ้าชีตนี้มีอยู่แล้วก่อนหน้า (แบบของพี่ตอนนี้) ต้องรันฟังก์ชันแพตช์นี้ครั้งเดียว — รันซ้ำได้ปลอดภัย ระบบจะเช็คเองว่าตารางไหนมีอยู่แล้วไม่เพิ่มซ้ำ:

1. วางโค้ด `Code.gs` เวอร์ชันนี้ทับของเดิม แล้วบันทึก
2. เลือกฟังก์ชัน **`addAsaProductivitySummaryToExisting`** จากดรอปดาวน์ข้างปุ่ม Run
3. กด **Run**
4. เปิดชีต `NurseSummary` เช็คว่ามีตาราง "สรุปคะแนน ASA Class..." ที่แถว 50 และตาราง "Productivity รายเวร..." ที่แถว 78 เพิ่มเข้ามาแล้ว
5. Deploy ใหม่ผ่าน Manage deployments (New version) เพื่อให้ URL เดิมใช้โค้ดล่าสุด

### เกี่ยวกับปุ่ม "ไม่มีเคสวันนี้ (ยืนยันเป็น 0)" ในแอป

เพิ่มช่องนี้ไว้ในทั้งสองหมวด (P4P ผู้ช่วย และ P4P Nurse) เพื่อแยกแยะระหว่าง **"ลืมกรอกข้อมูล"** กับ **"ไม่มีเคสจริงในวันนั้น"**
เมื่อกดยืนยัน ระบบจะบันทึกแถวพิเศษ (แต้ม = 0) ลง RawLog เพื่อให้ระบบแจ้งเตือนรู้ว่าจุดนั้น "รายงานแล้ว" แม้ไม่มีงานเกิดขึ้นจริง จะได้ไม่ถูกฟ้องว่ายังไม่ลงข้อมูลทั้งที่ตรวจสอบแล้ว

**ข้อจำกัดที่ควรทราบ:** ระบบแยกแยะ "ลืมกรอก" กับ "ไม่มีเคสจริง" ได้ก็ต่อเมื่อมีคนกดยืนยันเป็น 0 เท่านั้น ถ้าไม่มีใครกดอะไรเลยที่จุดนั้น ระบบจะถือว่ายังไม่ได้ลงข้อมูลเสมอ (ไม่มีตารางเวรเชื่อมโยงในระบบเพื่อรู้ว่าจุดนั้นควรมีคนทำงานอยู่จริงหรือไม่)

## จุดที่ตั้งใจออกแบบให้แก้ปัญหาเดิม (เหมือนแอป P4P ผู้ช่วย)

- แก้ไข/ลบได้เฉพาะรายการของตัวเองในแท็บ "ประวัติวันนี้"
- ใช้งานได้แม้สัญญาณเน็ตหลุด แล้วซิงก์อัตโนมัติเมื่อกลับมามีสัญญาณ
