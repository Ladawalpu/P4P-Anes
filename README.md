# P4P AnesMNST (ต้นแบบ)

แอปมือถือแบบ PWA รวม 2 หมวดงานไว้ในแอปเดียว — เปิดมาเจอหน้าโฮมให้เลือกก่อนว่าจะกรอก
**"P4P ผู้ช่วย"** หรือ **"P4P Nurse"**

## ไฟล์ในชุดนี้

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | แอปทั้งหมด (หน้าโฮม + ผู้ช่วย + Nurse) อยู่ในไฟล์เดียว |
| `manifest.json`, `sw.js` | ติดตั้งเป็นไอคอนบนมือถือ + ใช้งานออฟไลน์ได้ |
| `Code.gs` | โค้ดฝั่งเซิร์ฟเวอร์ (Google Apps Script) รับข้อมูลทั้งสองหมวดไปเก็บคนละชีต |

## ทดลองใช้ทันที

เปิด `index.html` ในเบราว์เซอร์บนมือถือได้เลย จะเจอหน้าโฮมมีปุ่มใหญ่ 2 อัน:
- **P4P ผู้ช่วย** (สีฟ้า `#157FA6`) — เหมือนแอปเดิมทุกประการ
- **P4P Nurse** (สีม่วงคราม) — ของใหม่ตามที่คุยกัน

## สิ่งที่ต่างจากแอป "P4P ผู้ช่วย" เดิม (เพื่อรองรับ P4P Nurse)

### 1. เลือก "วันที่ปฏิบัติงาน" และ "เวร" แบบ dropdown
P4P Nurse มี dropdown 2 ช่องก่อนกรอกกิจกรรม:
- **วันที่ปฏิบัติงาน** — รายการวันที่ทั้งหมดในเดือนปัจจุบัน (ค่าเริ่มต้นคือวันนี้) ใช้กรอกย้อนหลังได้ถ้าลืมบันทึก
- **เวร** — เช้าในเวลา / เช้านอกเวลา / บ่าย / ดึก

ค่าทั้งสองนี้ถูกส่งไปเก็บพร้อมข้อมูลทุกครั้ง ทำให้แยกคำนวณคะแนนภาระงานราย เวรและรายวันได้ในชีต `NurseSummary`

### 2. หมวด "กิจกรรมหลัก P4P วิสัญญีพยาบาล"
ใช้รายการกิจกรรมและค่าคงที่ตามตาราง "แต้ม" ที่แนบมาโดยตรง (11 กิจกรรมหลัก) โดยแต้มต่อรายถูกคำนวณล่วงหน้าจาก:

```
แต้มต่อ 1 ราย = เวลามาตรฐานต่อหน่วย (นาที) × น้ำหนักกิจกรรม × จำนวนบุคลากร/ทีม
```

ตัวอย่าง: Pre visit = 30 นาที × 1.25 × 1 คน = 37.5 แต้ม/ราย, GA = 150 × 2 × 2 = 600 แต้ม/ราย
ตัวเลขเหล่านี้ฝังไว้เป็นค่าคงที่ในแอปแล้ว ผู้ใช้กดนับจำนวนรายอย่างเดียว แอปคำนวณคะแนนรวมให้เอง

### 3. ไม่มีการแยกตามจุดปฏิบัติงานในสูตรคะแนน

ตารางต้นฉบับคำนวณแต้มจากยอดรวมทั้งแผนกต่อเดือน ไม่ได้แยกคะแนนตามจุดปฏิบัติงาน
แอปยังคงให้เลือก "จุดปฏิบัติงาน" ไว้เพื่อประโยชน์ในการติดตามข้อมูลเชิงปฏิบัติการ แต่ไม่มีผลต่อการคำนวณคะแนน P4P โดยตรง

### 4. หมวด "ASA Class ผู้ป่วยที่ดูแล (รวมรับ-ส่งเวร)" — สำหรับคำนวณ Productivity แยกต่างหาก
เพิ่มหมวดนี้เพื่อเก็บจำนวนผู้ป่วยแยกตาม ASA 1-6 พร้อมค่าคงที่ Productivity ต่อคลาส (ASA1=3.52, ASA2=5.33, ASA3=6.64, ASA4=7.12, ASA5=7.53, ASA6=7.53)
**ข้อมูลชุดนี้เป็นคนละตัวชี้วัดกับคะแนน P4P** ในหมวดกิจกรรมหลัก — ใช้สำหรับคำนวณ Productivity (ตัวชี้วัดภาระงานเชิงความหนัก) แยกต่างหาก ไม่นำมารวมกับคะแนน P4P
แอปจะแยกแสดงคะแนนทั้งสองประเภทให้ชัดเจนทั้งตอนกรอกและในประวัติ ไม่ปนกัน

## ขั้นตอนเชื่อมข้อมูลเข้า Google Sheet กลาง

เหมือนขั้นตอนเดิมของแอป P4P ผู้ช่วยทุกประการ (ดูละเอียดในโค้ดคอมเมนต์ของ `Code.gs`):

1. สร้าง Google Sheet ใหม่ 1 ไฟล์ (แนะนำใช้บัญชีองค์กรของ รพ.)
2. Extensions > Apps Script → วางโค้ดจาก `Code.gs` ทับของเดิม → บันทึก
3. Deploy > New deployment > Web app → Execute as: **Me** → Who has access: **Anyone** (หรือเฉพาะโดเมนองค์กร) → Deploy → คัดลอก URL (`/exec`)
4. เปิดแอป กดไอคอนเฟือง (⚙) วาง URL เดียวกันนี้ได้เลย — **ใช้ URL เดียวกันทั้งสองหมวด** ระบบจะแยกเก็บลงชีตคนละแผ่นให้อัตโนมัติ:
   - `RawLog_Assistant` / `AssistantSummary` — ข้อมูลจาก P4P ผู้ช่วย
   - `RawLog_Nurse` / `NurseSummary` — ข้อมูลจาก P4P Nurse

## เกี่ยวกับ NurseSummary

ชีต `NurseSummary` คำนวณ**คะแนนภาระงานรวมต่อเวร** ให้อัตโนมัติจากข้อมูลที่กรอกทุกวัน (เดือนปัจจุบัน) ไม่ต้องกรอกอะไรเพิ่มเอง
พร้อมตารางสรุปคะแนนต่อกิจกรรม x จุดปฏิบัติงานให้ดูภาพรวมเชิงปฏิบัติการเพิ่มเติมด้านล่าง

## สรุปยอดรวมรายกิจกรรมทั้งเดือน (สำหรับส่งต่อทีมคำนวณค่างาน)

ทั้ง `AssistantSummary` และ `NurseSummary` มีตารางเพิ่มเติมด้านล่าง (แถวที่ 30 เป็นต้นไป) ชื่อ **"สรุปยอดรวมรายกิจกรรมทั้งเดือน"**
เป็นยอดรวมแบบเรียบง่าย ไม่แยกตามจุดปฏิบัติงาน/เวร — เหมาะสำหรับให้ทีมที่รับผิดชอบคำนวณค่างานคัดลอกไปใช้ต่อตอนสิ้นเดือน
(นำไปเชื่อมกับข้อมูลจำนวนวันทำงานรายบุคคลเองภายหลัง เนื่องจากข้อมูลนั้นสรุปได้ต่อเมื่อสิ้นเดือนเท่านั้น)

## แก้ปัญหาข้อมูลซ้ำ (ถ้าเคยเจอบันทึกซ้ำหลายครั้งจากการกดครั้งเดียว)

**สาเหตุที่เคยเกิด:** Apps Script Web App บางครั้งตอบกลับแอปฝั่งไคลเอนต์ไม่สำเร็จ (ทั้งที่จริงบันทึกลงชีตสำเร็จแล้ว) ทำให้ระบบ retry อัตโนมัติ (ทุก 20 วินาที) ส่งข้อมูลเดิมซ้ำไปเรื่อยๆ โดยไม่รู้ตัว

**แก้แล้วในโค้ดเวอร์ชันนี้:** เพิ่มการเช็คที่ฝั่งเซิร์ฟเวอร์ว่าถ้ามี entryId+activityId นี้อยู่แล้ว จะไม่บันทึกซ้ำ ดังนั้นถึงระบบ retry ซ้ำอีกก็จะไม่เพิ่มแถวซ้ำแล้ว

**ลบข้อมูลซ้ำที่เกิดไปแล้วก่อนหน้านี้ (ทำครั้งเดียว):**
1. วางโค้ด `Code.gs` เวอร์ชันนี้ทับของเดิมใน Apps Script แล้วบันทึก
2. เลือกฟังก์ชัน **`removeDuplicateRows`** จากดรอปดาวน์ข้างปุ่ม Run
3. กด **Run** — ระบบจะไล่ลบแถวที่ซ้ำกันในทั้ง `RawLog_Assistant` และ `RawLog_Nurse` ให้อัตโนมัติ เหลือไว้แค่รายการแรกของแต่ละครั้งที่บันทึกจริง
4. เปิด **View > Logs** (หรือ Ctrl+Enter) เพื่อดูว่าลบไปกี่แถวในแต่ละชีต

### วิธีเปิดใช้งาน (ทำครั้งเดียว)

1. วางโค้ด `Code.gs` เวอร์ชันนี้ทับของเดิมใน Apps Script แล้วบันทึก
2. ที่แถบด้านบนของหน้า Apps Script เลือกฟังก์ชัน **`setupDailyMissingCheckTrigger`** จากดรอปดาวน์ (ข้างปุ่ม Run รูปสามเหลี่ยม)
3. กด **Run** — ครั้งแรกจะมีหน้าต่างขอ Authorize สิทธิ์ส่งอีเมล ให้กด Authorize access แล้วเลือกบัญชี (อาจมีหน้าเตือน "Google hasn't verified this app" ให้กด Advanced > Go to [ชื่อไฟล์] (unsafe) ได้ตามปกติ)
4. เสร็จแล้ว ระบบจะรันอัตโนมัติทุกวันเวลา 19:00 น. โดยไม่ต้องทำอะไรเพิ่ม — ตรวจสอบได้ที่เมนู Triggers (ไอคอนนาฬิกาทางซ้าย) ว่ามี trigger ของฟังก์ชัน `checkMissingLocations` ขึ้นอยู่

## เพิ่มตาราง ASA Productivity เข้าไปในชีต NurseSummary ที่มีอยู่แล้ว (ทำครั้งเดียว)

ฟังก์ชัน `ensureNurseSummary` จะสร้างตาราง ASA ให้อัตโนมัติ**เฉพาะตอนสร้างชีต NurseSummary ใหม่ครั้งแรกเท่านั้น** ถ้าชีตนี้มีอยู่แล้วก่อนหน้า (แบบของพี่ตอนนี้) ต้องรันฟังก์ชันเพิ่มเติมนี้ครั้งเดียว:

1. วางโค้ด `Code.gs` เวอร์ชันนี้ทับของเดิม แล้วบันทึก
2. เลือกฟังก์ชัน **`addAsaProductivitySummaryToExisting`** จากดรอปดาวน์ข้างปุ่ม Run
3. กด **Run**
4. เปิดชีต `NurseSummary` เช็คว่ามีตาราง "สรุปคะแนน ASA Class สำหรับคำนวณ Productivity" เพิ่มเข้ามาที่แถว 50 เป็นต้นไป
5. Deploy ใหม่ผ่าน Manage deployments (New version) เพื่อให้ URL เดิมใช้โค้ดล่าสุด

### เกี่ยวกับปุ่ม "ไม่มีเคสวันนี้ (ยืนยันเป็น 0)" ในแอป

เพิ่มช่องนี้ไว้ในทั้งสองหมวด (P4P ผู้ช่วย และ P4P Nurse) เพื่อแยกแยะระหว่าง **"ลืมกรอกข้อมูล"** กับ **"ไม่มีเคสจริงในวันนั้น"**
เมื่อกดยืนยัน ระบบจะบันทึกแถวพิเศษ (แต้ม = 0) ลง RawLog เพื่อให้ระบบแจ้งเตือนรู้ว่าจุดนั้น "รายงานแล้ว" แม้ไม่มีงานเกิดขึ้นจริง จะได้ไม่ถูกฟ้องว่ายังไม่ลงข้อมูลทั้งที่ตรวจสอบแล้ว

**ข้อจำกัดที่ควรทราบ:** ระบบแยกแยะ "ลืมกรอก" กับ "ไม่มีเคสจริง" ได้ก็ต่อเมื่อมีคนกดยืนยันเป็น 0 เท่านั้น ถ้าไม่มีใครกดอะไรเลยที่จุดนั้น ระบบจะถือว่ายังไม่ได้ลงข้อมูลเสมอ (ไม่มีตารางเวรเชื่อมโยงในระบบเพื่อรู้ว่าจุดนั้นควรมีคนทำงานอยู่จริงหรือไม่)

## จุดที่ตั้งใจออกแบบให้แก้ปัญหาเดิม (เหมือนแอป P4P ผู้ช่วย)

- ห้ามแก้ไขชีตข้อมูลดิบโดยตรง — เขียนได้ผ่านสคริปต์เท่านั้น
- ไม่มีปัญหาสิทธิ์เปิดลิงก์ พนักงานเข้าผ่านหน้าเว็บแอปอย่างเดียว
- กันกรอกผิดด้วยปุ่ม +/- และ dropdown เท่านั้น
- แก้ไข/ลบได้เฉพาะรายการของตัวเองในแท็บ "ประวัติวันนี้"
- ใช้งานได้แม้สัญญาณเน็ตหลุด แล้วซิงก์อัตโนมัติเมื่อกลับมามีสัญญาณ
